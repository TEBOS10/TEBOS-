# ADR 0017: Grok (xAI) as a reasoning provider

Date: 2026-11-01 · Status: built, off until the founder sets the key (operator log, decision 36).

## Context

The founder asked, on 1 Nov: "TEBOS needs to connect to grok." TEBOS is already model-agnostic (dossier §49):
the worker asks a `ReasoningProvider` for an answer that follows a JSON schema, then validates that answer
itself before anything is stored. Two providers existed: Claude (`anthropic-provider.ts`) and TEBOS's own
OpenAI-compatible model gateway (`gateway-provider.ts`), chained by `FallbackProvider`.

xAI's API speaks the same chat-completions format at `https://api.x.ai/v1`, and supports schema-constrained
answers (`response_format: json_schema`, `strict: true`). Its documentation names `grok-4.7` as the current model.

## Decision

1. **Grok is a third provider, built on the gateway provider.** `src/intelligence/xai-provider.ts` points the
   existing `GatewayProvider` at xAI, under the name `xai`. There is no new SDK and no new dependency. The gateway
   provider now takes an optional name and label, so errors say "xAI rejected the credentials" and not
   "the model gateway".
2. **Where it sits: Claude, then Grok, then the gateway.** Each provider is used only when the one before is
   unavailable or misconfigured; a refusal or a bad answer is never retried elsewhere (unchanged rule). With
   only `XAI_API_KEY` set, Grok runs alone.
3. **Nothing changes about trust.** Grok's answers are proposals, validated by the same deterministic checks as
   Claude's. Its answers don't skip approvals, and it can't send, pay or change anything by itself.
4. **Worker only.** The key lives in Railway as `XAI_API_KEY`, set by the founder. It is never in a web app (the
   bundle check now also forbids `grok` and `api.x.ai` in every web bundle), never in chat, never logged. The
   worker's start-up line names the providers in use (e.g. `anthropic+xai`), never a key.
5. **Off until configured, and the cost is the founder's.** With no key nothing happens and nothing is spent. Before
   setting the key the founder sets a monthly spending limit in xAI's console and confirms API data isn't used for
   training, because the worker sends clients' business data (the same rule as the gateway's paid routes).

## Not done

- **Grok inside the founder's chat (TEPOS / REEDS) or as a client that takes work through the Model Bridge.** This
  connects Grok as TEBOS's reasoning. A Grok chat window in the interface would need its own decision.
- **Live verification.** No key exists yet, so no request to xAI has been made. The tests use a fake endpoint.
  After decision 36, check the start-up line and the next analysis run.
